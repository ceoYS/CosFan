# Reference: Duolingo / Imprint / Walmart - notification opt-in priming (benefit-first)

- source_app: Duolingo (primary), with Imprint, Walmart, Yahoo Finance, DICK'S Sporting Goods as corroborating examples (iOS)
- mobbin_category: Onboarding / Permission priming
- screen_type: Pre-permission "soft ask" screen — illustration + benefit statement + "Turn on / Enable notifications" primary and a low-key dismiss
- target_cosfan_screen: Notification opt-in priming (before the OS permission dialog)
- user_job: "Decide whether push is worth it — show me what I'd actually get before iOS asks."
- first_visible_promise: A benefit-framed headline, NOT a system ask. Duolingo: "I'll cheer you on from your home screen!" (widget) / habit framing; Imprint: "Turn on notifications to get the most out of Imprint" with a visual of the value loop; Walmart: "Get order and savings updates"; Yahoo Finance lists exactly what alerts you'll receive.
- primary_cta: "Enable Notifications" / "Turn on notifications" / "Get notifications" (full-width, high emphasis). Tapping it triggers the real iOS permission sheet.
- secondary_cta: Low-emphasis dismiss — "Not now" / "Maybe later" / "Skip this step" (kept visually quiet so the default leans toward opting in, but the escape always exists).
- section_order: 1) Illustration or sample notification cards -> 2) Benefit headline -> 3) (often) a short bulleted list of what you'll receive -> 4) primary Enable button -> 5) quiet dismiss link.
- trust_elements: Showing realistic sample notification bubbles (Walmart, DICK'S, Best Buy) makes the value concrete; enumerating alert types (Yahoo Finance) sets honest expectations and signals "no spam"; reassurance like "you can mute anytime in settings" (Linktree) lowers commitment risk.
- friction_removed: Decouples the value pitch from the OS yes/no, so the user understands the benefit BEFORE the un-reversible system prompt — this both raises opt-in rate and avoids "burning" the permission on a confused no. One tap to accept; dismissing is one tap too.
- empty_loading_error_handling: N/A (static screen); the only state is accept vs defer. Deferring still lets the app re-ask contextually later.
- monetization_exposure: Indirect — several examples lead with deals/offers ("savings updates", "early-access discounts"), but no purchase happens here.
- onboarding_step: Late onboarding, AFTER the user has selected interests/creators (so the benefit is personalized: "get notified when creators you follow post").
- mobile_pattern: Benefit-first permission priming screen (soft ask) preceding the native dialog; high-emphasis enable + quiet defer; optional sample-notification visuals and alert-type list.
- why_relevant_to_cosfan: CosFan lives or dies on push ("your favorite cosplayer just posted / dropped a new photocard"). This pattern says "here's the value of turning on push"; it persuades the fan who would reflexively deny the OS prompt. Placed AFTER creator selection so the copy can be specific and compelling. It reduces the fear of spam by enumerating what's sent. Reusable structure: illustration + personalized benefit + enable/defer, with the native prompt fired only on accept.
- what_to_learn: Always show a soft-ask priming screen before the iOS dialog. Personalize the benefit to what the user just chose ("Get notified the moment <creators you follow> post or drop a new card"). Enumerate notification types to signal no-spam. Keep "Not now" present but quiet. Fire the OS prompt only when the user taps Enable.
- what_not_to_copy: Don't copy Duolingo's owl/green or the various brands' illustrations; render with CosFan pastel + a clean white card and a small CosFan-style graphic. Avoid leading with discounts/deals as the hook (that drifts toward a retail/PPV tone) — lead with the fandom/creator-update value instead. Don't use guilt or dark-pattern phrasing on the dismiss.
- risk_notes: Over-promising frequency or leading with "offers/promotions" can read as spammy or commerce-y, undermining the wholesome fan vibe; keep the promise honest and creator-centric. Never make "Not now" hard to find (dark pattern) — that erodes the trust CosFan needs.
- MVP_action: Add a notification priming screen right after creator/genre selection: clean white card, small pastel illustration, headline like "Never miss a drop" with subcopy naming the creators they follow, a short 2-3 item list of what's sent (new posts, photocard drops, member-only updates), a pastel "Turn on notifications" primary and a quiet "Maybe later". Trigger the iOS prompt only on tap.
